# Lab Inventory — Task 7 (PWA)

Task 6 (Next.js, Firebase auth, TanStack Query) turned into an installable, offline-capable PWA.
All earlier features are kept: routing, CRUD, filters, dashboard, auth, query caching.

## What was added

| Requirement | Where |
| --- | --- |
| Manifest (`name`, `short_name`, `start_url`, `scope`, `standalone`, colors, 192/512 icons) | `public/manifest.json`, linked via `metadata.manifest` in `app/layout.tsx` |
| Icons | `public/icons/*` (generated by `scripts/generate-icons.mjs`) |
| Service worker (install / activate / fetch) | `pwa/sw.template.js` -> `public/sw.js` (generated on every build by `scripts/generate-sw.mjs`) |
| Precache of shell, JS/CSS, icons, `/offline` | install step; the JS/CSS list comes from `scripts/generate-precache.mjs` (runs after `next build`) |
| Versioned caches + cleanup | `lab-shell-<v>`, `lab-pages-<v>` are deleted on `activate` when the version changes |
| Update flow | `components/PwaProvider.tsx`: "Update now" bar -> `SKIP_WAITING` -> `controllerchange` -> reload |
| Cache-first | `/_next/static/*`, images, icons, fonts (`lab-assets-v1`, max 60 entries) |
| Network-first (4 s timeout) | `/api/items*` (`lab-api-v1`, max 50) and page navigations (`lab-pages-<v>`, max 30) |
| Public API | `app/api/items`, `app/api/items/[id]` (read-only catalog). Edits made by the user are an overlay in `localStorage` (`services/service.ts`) |
| "Viewing cached data" notice | SW adds `x-sw-cache: hit`; `lib/connectivity.ts` + `components/OfflineBanner.tsx` |
| Online/offline indicator | `components/ConnectionStatus.tsx` in the header |
| `/offline` page + Retry | `app/offline`, `components/views/OfflineView.tsx` (Retry makes a real request) |
| Privacy | Only same-origin GETs are handled. Firebase/Google (cross-origin) requests, requests with `Authorization`, and `/profile` are never cached |
| Mobile | hamburger menu (`NavBar`), 44px touch targets, 16px inputs, tested at 320px portrait and landscape with no horizontal scroll |

## Run

```bash
npm install
cp .env.example .env.local   # Firebase keys
npm run build && npm start   # the service worker only registers in production
```

## Test the PWA

1. Open the site in Chrome, DevTools -> Application: Manifest, Service Workers, Cache Storage.
2. Visit `/items` and a details page, then tick **Offline** (or stop the server) and reload.
   The cached pages work and the yellow "viewing saved data" bar appears.
3. Open an unvisited page offline -> `/offline`. Press **Retry connection** after reconnecting.
4. Deploy a new build -> "A new version is available" bar -> **Update now**.
